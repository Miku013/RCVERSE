# 開発経緯・開発過程・修正内容記録 (DEVELOPMENT HISTORY)

本ドキュメントでは、MODの着想から現在に至るまでの開発経緯、直面した技術的課題、そしてそれを解決した物理・ネットワーク同期の進化過程を詳細に記録します。

---

## 1. 開発のタイムラインと変遷

### Phase 1: マイクロドローンの誕生
- **目的**: 卓上サイズ（手のひらサイズ）の超小型FPVドローンをMinecraftの世界で自由に飛ばす。
- **実装**:
  - GeckoLibによるリアルな4ローター3Dモデルとペラ回転。
  - アングルモード（水平自律復帰）とアクロモード（3D自由宙返り）のフライトコントローラー。
  - プロポを持った操縦者の立ち位置からの電波距離・減衰シミュレーション。

### Phase 2: RCシリーズへの拡張（陸・海・空・戦）
- **目的**: ドローンの操縦基盤を共有し、ラジコンカー、戦車、飛行機、ボート、潜水艦へマルチ展開。
- **実装**:
  - `RcControllable` および `RcVehicleClientController` ストラテジーパターンの導入。
  - 単一の入力ハンドラー（`ClientDroneInputHandler`）から機体種別に応じたコントローラーへ入力を自動ディスパッチ。
  - 航空力学（プレーン）、浮力・水密物理（ボート・潜水艦）、砲塔旋回と反動（戦車）の確立。

### Phase 3: サーキットコース＆スプライン道路生成
- **目的**: RCカーのスピードを最大限に引き出す専用サーキットと、滑らかな峠道・ヘアピンカーブの自動生成。
- **実装**:
  - スプライン道路生成システム（始点・終点マーカーからのプロシージャルメッシュ生成）。
  - モジュラースロープ、360度縦ループコース、ラップタイマー、チェックポイント。

### Phase 4: 車両拡張システムとディテールアップ（86・リトラクタブル・自転車）
- **目的**: 外部JSONによる車両追加、ヘッドライト開閉、村人自転車の搭乗アクション。
- **実装**:
  - `CarConfig` による動的ロード基盤。
  - 86のリトラクタブル開閉、夜間実照明追従配置（`Blocks.LIGHT` level 15）。
  - 村人自転車モデルの一体化と、クランク・太もも・すね・上半身のダンシング連動アニメーション。

## 2. 直面した技術的課題と徹底的解決 (Exhaustive Problem & Fixes)

開発過程で発生した難題と、その解決策の全容です。

### 課題 1: スロープ進入時の段差衝突（引っ掛かり）とメッシュ下への沈み込み
- **問題**: マイクラ標準のバウンディングボックス（VoxelShape）は階段状の段差になるため、高速進入時に車輪が段差にぶつかって急停止したり、スロープブロックの下にめり込む現象が発生。
- **解決策**:
  - RCカー側のスロープ判定を `VoxelShape` から独立させ、ブロックエンティティが保持する三角形メッシュ（ポリゴン）の正確な法線ベクトルと高さを直接計算。
  - 路面から浮かないよう、法線方向に下向きの吸引力（サスペンション吸着）をかけることで、斜面やバンク角45度の壁面でも一切跳ねることなく路面に吸い付く走りを実現。

### 課題 2: ジャンプ台踏み切り時の即時落下（バニーホップ化）
- **問題**: ジャンプ台の先端を飛び出した瞬間にMinecraftの通常落下重力がかかり、放物線を描かずにストンと真下に落ちてしまう。
- **解決策**:
  - スロープ離脱時に「ノーズアップ慣性（Nose-up Inertia）」を保持。
  - 上昇中は重力を軽減し、頂点を過ぎてから徐々に重力ブースト（1.8倍）をかける「ハイブリッド放物線物理」を実装。これにより、実車スタントのような綺麗な放物線ジャンプを実現。

### 課題 3: ジャンプ着地後の斜めドリフト・引き戻し同期バグ
- **問題**: 空中ジャンプ中にステアリングを切ると、着地後に車体が斜め方向に引きずられるような違和感が発生。
- **解決策**:
  - 原因はクライアント側でサーバー座標への「ソフトプル（緩慢な位置補正）」を行っていたため、空中での予測位置とサーバー位置の微小なズレが斜めベクトルとして合成されていたこと。
  - クライアント主導のローカル物理を強化し、余分なソフトプルを完全撤廃。サーバーへは高頻度で確定座標・速度・角度を同期（Yaw同期）することで、着地後も狙った方向へ正確にトレースできるように修正。

### 課題 4: 操縦中のディスクI/O高負荷＆ログスパム
- **問題**: 長時間操縦していると、フレームタイム警告ログがコンソールおよび `latest.log` に毎秒数十回書き込まれ、フレームレート低下の原因になっていた。
- **解決策**:
  - ログ警告にスロットリング（時間抑制カウンター）を導入し、同一警告の連続書き込みを遮断。ディスクI/Oを極小化。

### 課題 5: ジャンプパッド（Jump Pad）の引っ掛かりと打ち上げ挙動の進化
- **問題**: プレートにわずかでも当たり判定（コライダー）があると、超高速で進入した際に車体が衝突判定を受けて失速した。また、真上に垂直ジャンプするだけだとコース進行の妨げになった。
- **解決策**:
  - ジャンプパッドのブロック形状を `Shapes.empty()`（コライダー完全透明）に変更。段差衝突を物理的に不可能にした。
  - 打ち上げ挙動を「**2段階カタパルト物理**」へ刷新。踏み込み時は垂直に一気にロケット上昇し、頂点（Apex）に達した瞬間、前方の足場へ向けてシュッと水平吐き出し（Apex Expel）を行うダイナミックな空中移動を実現。

### 課題 6: 自転車前輪の横回転（コマ回しスピン）バグ
- **問題**: 村人自転車を導入した際、後輪は縦に転がるのに、前輪（`wheel_f`）だけが地面と水平に横回転してしまう現象が発生。
- **解決策**:
  - 原因: Blockbenchのモデル構造において、親フォーク（`fork_and_handle`）が `Z=-90°`、子ホイール（`wheel_f`）が `Z=+90°` で作成されていた。
  - 合算するとワールド空間では直立（Z=0°）しているにもかかわらず、子ボーン単体の初期値に90°が入っていたため、既存のバギー四輪用「横倒し判定（`isLyingOnZ`）」が誤爆し、ローカルY軸（鉛直軸）を回転させていた。
  - `wheel_f` の初期Z回転（+90°）を保持したまま、左右車軸（ローカルX軸）で回転させる専用処理を組み込み、まっすぐ縦に転がるよう修正。
